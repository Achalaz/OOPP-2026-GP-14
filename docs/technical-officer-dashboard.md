# Technical Officer dashboard

This phase adds dashboard presentation and basic navigation. The existing login
continues to authenticate accounts, and `NavigationUtil.dashboardResource()` routes
active `TECHNICAL_OFFICER` sessions to `/fxml/technical_officer_dashboard.fxml`.
`MainApp`, authentication, User/DAO models, academic calculations, and the existing
Attendance/Medical modules have not been changed.

## Available UI

- Navy sidebar with FTMS branding, officer name, and secure logout.
- Current date, welcome banner, department placeholder, and five feature cards.
- Three, two, or one card columns according to available content width.
- Independently scrollable navigation and main content; logout remains accessible.
- Native window decorations and the current window size are preserved during portal
  navigation. Returning to the dashboard does not start or clear a session.
- My Profile opens the existing owner-bound profile screen. That workflow supports
  name, email, and picture updates. Username and role are read-only, and no password
  editor exists. Its service/DAO update only personal details or the picture reference.
- Attendance, Medical, Notices, and Department Timetable display the information
  dialog **This feature will be available soon.** Each has its own controller handler.

The dashboard itself makes no database queries. Opening My Profile uses the existing
profile module and its normal asynchronous database reads. No records or statistics
are fabricated. The department label is a placeholder, not an assertion that an
officer has no assigned department.

## Schema and future integration

Read-only inspection of the configured MySQL database on 2026-10-18 confirmed:

- `users.role`: `enum('ADMIN','LECTURER','STUDENT','TECHNICAL_OFFICER')`.
- `technical_officers.technical_officer_id` references `users.user_id`.
- `users.department_id` is nullable and references `departments.department_id`.
- `courses.department_id` also references `departments.department_id`.
- The current `User` model/session does not expose department membership;
  `TechnicalOfficer`, `Department`, and `DepartmentDAO` are presently stubs.

No DDL or data writes were executed. The dashboard requires no migration.

Future attendance and medical integration must reuse existing business logic behind
services/DAOs that revalidate the active officer account, login identity, and authorized
department for every read/write. Resolve scope from trusted account mappings, not an
editable department/student/offering ID. Missing department mappings must not imply
access to all departments. Confirm the permitted medical scope with the module owner;
this dashboard grants no approve/reject permissions.

Notices must be read-only and limited to published notices. Timetables must be
read-only and constrained to the officer's verified department. The existing generic
attendance/medical management screens are not linked: they expose broader operations
and do not yet implement Technical Officer department authorization. Navigation
restrictions are not a replacement for the future service/DAO checks, including for
legacy screens loaded directly outside `NavigationUtil`.

## Preview

For the real application, run the existing Maven JavaFX entry point and sign in with
an existing active Technical Officer account. No preview account or login bypass was
added. Use My Profile -> Back to Dashboard to return with the same session.

For a static design preview without credentials, open
`src/main/resources/fxml/technical_officer_dashboard.fxml` in Scene Builder. Its
relative CSS reference loads `../css/technical_officer_dashboard.css`. Use the design
canvas or Scene Builder preview without removing the controller/security checks.
The FXML's default design has two columns; automatic card reflow and actions run in
the JavaFX application, not in the static design canvas.

Executed with Java 25.0.4.1, JavaFX 25, and Maven 3.8.5:

- Maven `compile` and `test-compile`: BUILD SUCCESS.
- `TechnicalOfficerDashboardSmokeTest --snapshot --live-profile`: **369 checks passed**.
  Covers injected fields, placeholder handlers, unauthorized roles/stale sessions,
  navigation restrictions, existing Admin/Lecturer/Student route and FXML loading,
  Dashboard/Logout, profile forward/back from both entry points, profile logout,
  read-only username/role and absent password controls.
- Layout checks at 1280x720, 1100x690, 900x600, 760x540, and 640x480. Wide and laptop
  snapshots and the complete card grid were visually inspected.
- Existing `ProfileServiceTest`: **79 checks passed**.
- Existing `ProfileViewSmokeTest`: **241 checks passed** across all four roles.
  Its synthetic duplicate-email/connection stack traces are expected test output.
- MySQL schema metadata and the existing officer profile were read. No database
  writes, committed profile edits, migrations, or academic operations were tested.

These are explicit `main` runners, not automatically executed JUnit tests. The new
runner uses in-memory test sessions; `--live-profile` selects an existing active
officer for profile read/navigation checks. It never submits a save or upload.
Credential-entry login, committed profile/picture persistence, and manual checks
across multiple monitors/Windows scaling settings were not executed in this task.

After `mvn test-compile`, run from the project root in PowerShell:

```powershell
$officerRepository = Join-Path $env:USERPROFILE '.m2/repository'
$officerModules = (Get-ChildItem "$officerRepository/org/openjfx/*/25/*-25-win.jar").FullName -join ';'
$officerClasspath = 'target/classes;target/test-classes'
java --module-path $officerModules --add-modules javafx.controls,javafx.fxml --enable-native-access=javafx.graphics -cp $officerClasspath lk.ac.ruhuna.ftms.controller.TechnicalOfficerDashboardSmokeTest --snapshot

# Optional existing-profile read checks; requires the existing configured MySQL server.
$officerMysql = Join-Path $officerRepository 'com/mysql/mysql-connector-j/9.4.0/mysql-connector-j-9.4.0.jar'
java --module-path $officerModules --add-modules javafx.controls,javafx.fxml --enable-native-access=javafx.graphics -cp "$officerClasspath;$officerMysql" lk.ac.ruhuna.ftms.controller.TechnicalOfficerDashboardSmokeTest --snapshot --live-profile
```

Maven is not currently on this machine's PATH. The existing installation under
`~/.m2/wrapper/dists/apache-maven-3.8.5-bin/` was used with the existing dependency
cache; no dependencies or project build configuration were changed.
